## Сценарии

Бэкенд-приложение по текстовому префиксу возвращает список релевантных подсказок (фраз) для поля поиска. Референс: Google Autocomplete, Яндекс Подсказки, Elasticsearch Completion Suggester.

1. Подсказки при вводе. Пользователь печатает запрос в строке поиска → сервис возвращает до _K_ подсказок, начинающихся с введённого префикса; при выборе подсказки строка поиска заполняется выбранной фразой.
2. Сортировка по релевантности/популярности. Среди подсказок, соответствующих префиксу, выше показываются более популярные (с большим весом).
3. Оперативное обновление словаря. Оператор загружает новый словарь — изменения начинают применяться без перезапуска.
4. Учёт выбора (этап 3). Когда пользователь выбирает подсказку, её популярность растёт.

## Функциональные требования

- Поиск по префиксу: возвращать только фразы, которые начинаются с заданного префикса; лимит результатов — _K_ (по умолчанию 10, от 1 до 50).
- Сортировка: по убыванию веса, при равном весе — по тексту в алфавитном порядке; порядок детерминирован.
- Нормализация ввода: регистронезависимость; обрезка пробелов по краям и схлопывание повторяющихся пробелов. `"Python  Tutorial "` и `"python tutorial"` — одна и та же фраза. (Опечатки, лемматизация, синонимы — не требуются.)
- Управление словарём: загрузка словаря целиком (`PUT /phrases`, существующие фразы обновляются) и точечное добавление фразы (`POST /phrases`) без рестарта.
- Персистентность: словарь и веса не теряются при перезапуске сервиса.
- Этап 3: выбор подсказки (`POST /queries`) увеличивает её популярность асинхронно, через очередь; итоговый вес = исходный вес + число выборов, изменение видно в выдаче не позднее чем через 5 секунд.
- Этап 3: подсказки по уже запрошенному префиксу продолжают отдаваться, когда PostgreSQL недоступен.

## Нефункциональные требования

- DAU (уникальных пользователей в день) — 10 000, MAU (в месяц) — 100 000.
- p95 времени ответа основного эндпоинта — меньше 100 мс.
- Доступность — 99,5 %.
- Данные не теряются при перезапуске сервиса.

Допущения для оценки: активный пользователь делает 5 поисков в день, при каждом поиске вводит в среднем 6 символов, и на каждый символ уходит запрос подсказок; каждый пятый поиск заканчивается выбором подсказки; пиковая нагрузка в 5 раз выше средней. Словарь — 1 млн фраз средней длиной 30 символов, обновляется целиком раз в сутки.

## Контракт API

Полная спецификация — в [`docs/openapi.yaml`](openapi.yaml), её пишете вы на этом этапе. Обязательные операции:

| Метод | Путь | Тело | Ответ | Коды |
|---|---|---|---|---|
| PUT | `/phrases` | `{"phrases": [{"text": "python tutorial", "weight": 10}, ...]}` | `{"loaded": 2}` | 200; 422 — пустой список, пустой `text`, `weight < 0` |
| POST | `/phrases` | `{"text": "...", "weight": 1}` | `{"id", "text", "weight"}` | 201; 409 — фраза уже есть; 422 |
| GET | `/suggest?q=<префикс>&limit=<K>` | — | `{"query": "py", "suggestions": [{"text", "weight"}, ...]}` | 200; 422 — пустой `q`, `limit` вне 1–50 |
| GET | `/health` | — | `{"status": "ok"}` | 200; 503 — PostgreSQL (с этапа 3 и Redis) недоступен |

На этапе 3 добавляется:

| Метод | Путь | Тело | Ответ | Коды |
|---|---|---|---|---|
| POST | `/queries` | `{"text": "python tutorial"}` | пусто | 202; 422 — пустой текст |

Ошибки — JSON `{"detail": "..."}`, ошибки валидации — 422 в формате FastAPI.
